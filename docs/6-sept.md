# Доработка 6-sept

Исходная версия: `3617a29961cce6a82a5302b9e49eb436600ddcfa`.
Промпты и модельные профили не изменены.

## Реализованные изменения

| Пункт | Изменение |
| --- | --- |
| 1. Завершение запросов | Каждый принятый запрос имеет `request_id`. Сообщение `completed` приходит и после `silent`, ошибки или отмены. Голосовой запрос освобождается независимо от наличия ответа. |
| 2. Сессии | Запрос содержит `session_id`. Ответ направляется исходной сессии. Отключение TUI/Web отменяет только её незавершённые запросы; голос остаётся отдельным источником. |
| 3. Автономные задания | Все сохранённые задания проходят `begin → step → completion`. Приостановленные задания хранятся в общей очереди. MQTT передаёт значение исходного события, даже если другая задача приостановлена. Если исполнитель занят, новая активация ожидает. |
| 4. Управление заданиями | `stop`, `start`, изменение периода и новое задание меняют поколение записи. Устаревшие активации отменяются перед запуском или следующим шагом. Удаление и повторное использование номера не оживляет старые события. |
| 5. Интерфейсы | На соединение выделена ограниченная очередь отправки и отдельный поток. Статусы заменяются свежими. Переполнение очереди или таймаут отправки отключает клиента, не блокируя генерацию. |
| 6. Нагрузка | Общая очередь ограничена, часть мест зарезервирована для человека. Есть счётчик отказов, время ожидания, выполнения, обращений к модели и команд. Менеджер и разовый агент уступают управление между шагами. Диалоги голоса, человека и уведомлений используют разные контексты. |
| 7. Команды | Вывод каждого потока ограничен, при таймауте завершается группа процессов. Повтор идентичной команды с неопределённым результатом блокируется в рамках текущего ввода/активации. Возможности ограничиваются настройками runtime, а не промптом. Web получил проверку Origin и настройку ключа доступа. |
| 8. Доставка | SQLite сохраняет уведомления до отправки. Ошибки доставки повторяются с увеличением интервала до 300 секунд. Очередь восстанавливается после перезапуска. TUI/Web подтверждают получение и устраняют повторы в текущем сеансе. |
| 9. Модули | Общий CORE выделен в `agent_core`; другие бэкенды и голосовой интерфейс импортируются без LiteRT. Общая телеметрия вынесена из адаптеров. MQTT использует единый адрес брокера. Старые импорты CORE сохранены как переходные; исторический ManagerRuntime и старые TUI оставлены для совместимости, но новый CORE не использует старый путь активации заданий. |
| 10. Голосовой чат | После «Чат» следующие реплики принимаются без «Гена». После «Конец чата» возвращается ожидание ключа. Vosk определяет границы реплики, GigaAM даёт окончательный текст. Во время STT, обработки запроса и озвучивания микрофон закрыт. |

## Точные правила

- `stop`: запретить будущие активации; отменить ожидающие и приостановленные перед очередным шагом. Текущий шаг заканчивается, включая уже начатую команду.
- `delete`: удалить запись, таймер и привязку событий. Уже принятые события больше не соответствуют живой записи.
- `start`: разрешить будущие события; ранее отменённые события не восстанавливаются.
- `period`: установить новый период и начать отсчёт от изменения; старые активации имеют устаревшее поколение.
- При выключении CORE незавершённая работа завершается отменой на границе шага; команды и модельные вызовы не прерываются произвольно.
- Отключённый интерфейс не получает результат через вновь подключившийся клиент. Его контекст освобождается; голосовой чат имеет отдельный контекст между кратковременными голосовыми соединениями.
- При заполнении входной очереди новое событие отклоняется с записью в журнал. Переходы MQTT не объединяются; повторные активации одного таймера объединяются.
- Повтор уведомления после аварии возможен. Firebase подтверждает приём провайдером, а не показ на телефоне. При частичном отказе multicast повтор может затронуть и уже успешных получателей.
- Принятые входные события не сохраняются на диск. Постоянная очередь относится к результатам, а не к повторному исполнению команд.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `CAT_AGENT_MAX_PENDING` | `128` | Общий предел незавершённых запросов; восемь мест резервируются для человеческого ввода при обычном размере очереди. |
| `CAT_AGENT_ENABLED_SKILLS` | `shell,mqtt` | Включённые возможности runtime. Полноценный Bash не является изолированной песочницей; он работает с правами процесса CORE. |
| `CAT_AGENT_ALLOW_SHELL` | `1` | `0` запрещает запуск Bash через навык shell. |
| `CAT_AGENT_MAX_FILE_BYTES` | `65536` | Также ограничивает сохраняемый stdout и stderr команды, каждый отдельно. |
| `CAT_AGENT_COMMAND_TIMEOUT_SECONDS` | `20` | Таймаут команды и её дочерних процессов. |
| `CAT_AGENT_MQTT_HOST` / `CAT_AGENT_MQTT_PORT` | `192.168.0.21` / `1883` | Общие параметры мониторинга и MQTT-команд. |
| `CAT_AGENT_OUTBOX` | `/var/lib/cat-agent/outbox.sqlite3` | Постоянная очередь уведомлений. |
| `CAT_AGENT_WEB_HOST` | `127.0.0.1` | Адрес Web-сервера. Изменён относительно прежнего `0.0.0.0`. |
| `CAT_AGENT_WEB_TOKEN` | пусто | Ключ доступа; вводится кнопкой «Ключ доступа» в Web. Передаётся первым сообщением WebSocket, не в URL. |
| `CAT_AGENT_WEB_TRUSTED_NETWORK` | `0` | Явное разрешение сетевого доступа без ключа: `1`. |
| `CAT_AGENT_WEB_ORIGINS` | пусто | Допустимые Origin через запятую. Без настройки допускается Origin того же хоста и HTTP-порта интерфейса. |
| `CAT_AGENT_VOICE_RESPONSE_TIMEOUT` | `300` | Максимальное ожидание активности ответа CORE в голосовом клиенте, секунды; socket timeout относится к ожиданию чтения, а не всей длительности запроса. |

Ключ Web не шифрует соединение. Для доступа за пределами доверенной сети нужен TLS или SSH-туннель.
Дополнительные диалоговые контексты LiteRT используют уже загруженный движок, но требуют дополнительной памяти сессий/KV и первого прогрева префикса. Их реальное потребление и задержки нужно измерить на Radxa. В llama.cpp переключение контекстов может уменьшать повторное использование кеша слота.

## Обновление и проверка на Radxa

Сначала получить код и выполнить тесты — это не перезапускает действующие службы:

```bash
cd /opt/cat-agent
git pull --ff-only

PYTHONPATH=/opt/cat-agent/src /opt/litert-lm-venv/bin/python3 \
-m unittest discover -s tests -v
```

Затем остановить запущенные CORE и интерфейсы и запустить их прежними командами. Перезапускать CORE и Voice нужно вместе: новый Voice ждёт `completed`. Модельные профили и расположение моделей остались прежними.

Для прежнего Web-доступа в доверенной домашней сети без ключа запускать с явно выбранным режимом:

```bash
CAT_AGENT_WEB_HOST=0.0.0.0 CAT_AGENT_WEB_TRUSTED_NETWORK=1 ./start_web.sh
```

Практические проверки после тестов:

1. Обычный запрос через TUI, затем разовое задание без текста результата. Следующий запрос должен выполняться.
2. «Гена» → «Чат» → две реплики без ключа → «Конец чата». После закрытия снова требуется «Гена».
3. Во время многошаговой работы из TUI отправить голосовой запрос. Голос обслуживается между шагами; затем исходная работа продолжается.
4. Остановить ожидающее MQTT-задание: новое действие из старого события выполняться не должно.
5. Переключить TUI на Web во время запроса: ответ старому интерфейсу не должен появиться в новом.
6. Проверить уведомление без открытого интерфейса. При отключённой сети оно остаётся в outbox; после восстановления связи должно отправиться.

## Проверки в среде разработки

Добавлены регрессионные проверки жизненного цикла, приоритетов, отмены заданий,
устойчивой доставки, ограничения вывода, завершения дочернего процесса и голосового чата.
Реальная модель, аудиоустройства и сокеты Radxa этой среде недоступны. Успех тестов
с подставными модельными/аудиоклиентами не заменяет аппаратные проверки выше.

Итог локального прогона: 135 тестов прошли. Девять тестов с Unix-сокетами
заблокированы ограничением среды исполнения; модуль `test_litert_runtime`
не загрузился из-за отсутствующей библиотеки `litert_lm`. Тесты в репозитории
не помечены пропущенными: на Radxa штатный запуск выполняет их полностью.
Синтаксис всех 84 Python-файлов проверен отдельно.
