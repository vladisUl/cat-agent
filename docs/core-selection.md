# Выбор CORE

LiteRT и OpenAI CORE могут работать одновременно. По умолчанию они слушают
разные Unix sockets:

```text
/run/cat-agent/litert.sock
/run/cat-agent/openai.sock
```

Оба CORE используют общий Task SYSTEM и не создают отдельных копий реестра
TASK, таймеров или очереди запусков.

## Автоматический выбор

Обычные интерфейсные launcher'ы можно запускать без аргумента:

```sh
./start_tui.sh
./start_web.sh
./start_voice.sh
```

В этом режиме `scripts/select_core.sh` запрашивает:

```sh
./task_system.sh cores
```

и выбирает первый READY CORE в порядке:

```text
openai
litert
```

Если ни один CORE не READY, launcher завершается с ошибкой и печатает
полученный статус.

Автоматический выбор выполняется только при старте интерфейса. Уже подключённая
сессия не мигрирует на другой CORE посреди диалога.

## Явный выбор

Для административной проверки или привязки интерфейса к конкретному backend
можно передать один аргумент:

```sh
./start_tui.sh litert
./start_web.sh openai
./start_voice.sh litert
```

Допустимы только `litert` и `openai`. Неизвестное имя или больше одного
аргумента считаются ошибкой.

Явный выбор задаёт:

```text
CAT_AGENT_CORE_SOCKET=/run/cat-agent/<backend>.sock
```

и не зависит от текущего READY-статуса Task SYSTEM. Если выбранный CORE не
работает, ошибка проявится при подключении интерфейса.

## Низкоуровневый override

`CAT_AGENT_CORE_SOCKET` имеет приоритет над автоматическим и явным выбором.
Это предназначено для тестов, отладки и административных запусков:

```sh
CAT_AGENT_CORE_SOCKET=/tmp/debug.sock ./start_openai_agent.sh
CAT_AGENT_CORE_SOCKET=/tmp/debug.sock ./start_tui.sh openai
```

Override должен совпадать у CORE и интерфейса. Один и тот же путь нельзя
одновременно отдавать двум работающим CORE.

CORE блокирует адрес через `<socket>.lock`, удаляет при остановке только свой
Unix socket и допускает повторный запуск после аварии, если оставшийся socket
больше не слушается. Обычный файл, symlink или активный чужой socket по
выбранному пути не удаляются.

Файл блокировки может оставаться на диске после остановки; это нормально.

## Task SYSTEM и выбор диалогового CORE

Выбор CORE для Web/TUI/Voice и выбор исполнителя сохранённого TASK — разные
механизмы.

Интерфейс выбирает CORE один раз при подключении. Для TASK с
`executor=auto` общий Task SYSTEM самостоятельно выбирает READY OpenAI,
иначе READY LiteRT, при каждой выдаче нового RUN. Поэтому диалог через LiteRT
не заставляет автономные задания выполняться на LiteRT и наоборот.

`CAT_AGENT_TASK_SOCKET` задаёт адрес общего Task SYSTEM и не связан с
`CAT_AGENT_CORE_SOCKET`.

Подробнее: [task-system.md](task-system.md).

## Два Web gateway

Если требуется одновременно запустить два Web gateway, подключённых к разным
CORE, им нужны разные HTTP/WS-порты. Выбор CORE разделяет Unix socket модели,
но не создаёт отдельные сетевые порты автоматически.

Обычная домашняя конфигурация запускает один Web gateway и выбирает нужный CORE
через стандартный launcher.
