# Выбор CORE

LiteRT и OpenAI можно запускать одновременно прежними launcher'ами CORE:
`start_litert_agent.sh e4b` (или другой профиль) и `start_openai_agent.sh`.
По умолчанию они слушают соответственно `/run/cat-agent/litert.sock`
и `/run/cat-agent/openai.sock`, включая запуск через Python `-m`.

У интерфейсов теперь обязателен один аргумент — `litert` или `openai`:

```sh
./start_tui.sh litert
./start_web.sh openai
./start_voice.sh litert
./start_web_home.sh openai
```

`start_web_home.sh` передаёт выбор обычному Web launcher'у и сохраняет
настройки домашнего HTTPS-сервера. Запуск без аргумента или с неизвестным
CORE завершается сообщением об ошибке.

Для тестов и отладки `CAT_AGENT_CORE_SOCKET` имеет приоритет над выбором:

```sh
CAT_AGENT_CORE_SOCKET=/tmp/debug.sock ./start_openai_agent.sh
CAT_AGENT_CORE_SOCKET=/tmp/debug.sock ./start_tui.sh openai
```

Override нужно задать одинаково для CORE и его интерфейса. Не задавайте
один override двум работающим CORE: второй запуск завершится ошибкой.
CORE блокирует свой адрес файлом `<socket>.lock`, удаляет при остановке
только собственный сокет и позволяет повторный запуск после аварии,
если оставшийся сокет больше не слушается. Файл блокировки остаётся
на диске; это нормально. Обычные файлы, ссылки и активные сокеты
по выбранному пути не удаляются.

После обновления перезапустите CORE и интерфейсы. Настройки прогрева
и числа потоков не изменены. Для прямого запуска Python-модулей интерфейсов
задавайте `CAT_AGENT_CORE_SOCKET` явно: выбор аргумента реализован в shell launcher'ах.
Два Web gateway на одном хосте дополнительно требуют разных HTTP/WS-портов.
Разделение IPC не создаёт отдельных копий общих конфигураций и хранилищ задач.
