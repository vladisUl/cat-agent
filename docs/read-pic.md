# Чтение изображений в текущем диалоге

Модель вызывает `/work#read_pic.sh test.png` или `/work#read_pic.sh /test.png`. Runtime перехватывает команду:
отдельный shell-скрипт устанавливать не требуется. Поддерживаются PNG и JPEG
(расширения .png, .jpg, .jpeg); SVG не поддерживается.

Путь может быть указан с ведущим `/` или без него. В обоих случаях это
логический путь от RAM-каталога `<workspace>/data` (обычно
`/opt/model/data`), а не путь от корня Linux. Например и
`camera/test.png`, и `/camera/test.png` означают
`/opt/model/data/camera/test.png`. Подкаталоги разрешены. Выход из DATA через
`..` или симлинки запрещён.
Один файл — один вызов. Ограничение размера по умолчанию 20 MiB;
CAT_AGENT_MAX_IMAGE_BYTES задаёт другое положительное число байт.
Файл проверяется по расширению и сигнатуре; полное декодирование выполняет backend.

Менеджер и рабочий агент получают изображение в собственную историю.
Байты фиксируются при чтении: последующее изменение файла не меняет уже
прикреплённое изображение. Рабочему агенту должен быть назначен tool read_pic.
Если CAT_AGENT_ENABLED_SKILLS задан явно, в список надо добавить read_pic.
Без этой переменной инструмент включён по умолчанию.

OpenAI-совместимый клиент передаёт изображение в Chat Completions как
image_url с data URL (base64), вместе с текстовой историей. Сервер и выбранная
модель должны поддерживать этот формат.

LiteRT-LM включает vision_backend CPU у обоих Engine. При первом изображении
полная история переносится из текстовой Session в Conversation того же Engine:
публичный Session.run_prefill принимает только текст, а Conversation выполняет
модельную обработку изображения. Последующие вопросы и изображения продолжают
этот Conversation. Сброс диалога закрывает его и возвращает текстовую Session
к сохранённой основе. Никакая отдельная модель-описатель не используется.

Цена такого перехода: повторный prefill истории при первом изображении и память
дополнительного Conversation до сброса диалога. Это не обещание мгновенного
первого ответа с картинкой. Текстовые запросы до первого изображения используют
прежний путь с прогревом. Во время vision точный общий размер KV не сообщается
(resident_tokens=null): публичная статистика даёт только последний prefill.
Показатель prompt_seconds для vision соответствует TTFT и включает обработку
изображения и первый токен генерации.

Для llama.cpp инструмент возвращает явную ошибку неподдерживаемого backend.
Промпты пользователя не изменены. Парсер принимает и TOOL, и прежний SKILL.

## Проверка на устройстве

1. Обновить репозиторий и выполнить тесты:
   ```bash
   cd /opt/cat-agent
   git pull --ff-only
   PYTHONPATH=/opt/cat-agent/src /opt/litert-lm-venv/bin/python3 -m unittest discover -s tests -v
   ```
2. Перезапустить CORE выбранного backend.
3. Положить test.png в `/opt/model/data`.
4. Написать «Чат», затем «Посмотри test.png. Что изображено?».
5. Убедиться в логе, что модель вызвала read_pic.sh; спросить подробность
   о той же картинке без повторного указания файла.
6. Завершить «Конец чата» и проверить обычный текстовый запрос.

Локально: 146 тестов прошли; ещё девять проверок сокетов и модуль тестов
установленного LiteRT недоступны в среде разработки. Новые тесты проверяют
передачу данных менеджеру и агенту, продолжение истории, OpenAI payload,
миграцию LiteRT и очистку контекста. Реальную работу vision на Radxa и
удалённом OpenAI-совместимом сервере надо проверить отдельно.
